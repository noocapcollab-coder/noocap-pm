# PM lessons: WhatsApp

Mistakes the PM made once and the rule that came out of each.

## Every revised cut on a WhatsApp deal reaches Harsh with its Frame.io link
When: An editor finishes a cut (first or revised) for a WhatsApp deal, or Harsh asks for 'the link' / 'the updated link'
Do: Send Harsh the Frame.io link on WhatsApp for every round, named by round; when asked for the link, answer with the Frame.io link from EDIT TRACKER
Never: Never let an alert filter swallow a new round because its headline matches the last one, and never answer 'the link' with the Drive folder
Seen 1 time(s). Source: Harsh correction.
## WhatsApp deals get the cut link on WhatsApp
When: A cut is marked Send to Brand and the deal runs on WhatsApp (or has no email deal)
Do: Send Harsh the Frame.io link and caption on WhatsApp to forward, mark the row With Brand and move the card to 9- Approval.
Never: Never bounce a WhatsApp deal's cut back to In Review with an error.
Seen 1 time(s). Source: Harsh correction.
## A WhatsApp message only answers the question it replies to
When: The PM asked Harsh for something a brand needs (an account email, a code) and Harsh then sends an unrelated message or link
Do: Use a message as the answer only when it swipe-replies to the question or plainly gives what was asked for; otherwise ask again.
Never: Never put an unrelated link or text into a brand email as the answer.
Seen 2 time(s). Source: Harsh correction.
## Reject wins over Send, and never say nothing was sent when it was
When: Send and Reject are tapped on the same draft within seconds
Do: Check the draft just before it leaves and stop if it was rejected; if it already went, say so plainly and offer a correction.
Never: Never tell Harsh 'Nothing was sent' about an email that went out.
Seen 1 time(s). Source: Harsh correction.
## A WhatsApp ask names only what Harsh alone can give
When: A brand email needs work done (recording, editing, posting, a revised cut) rather than a fact, file, date or money decision from Harsh
Do: Send the work to the team or the creator through the video card and editor flow, and ask Harsh only for the missing fact (a date, a code, a price, a file only he holds). If the brand asked nothing he must answer, send him nothing.
Never: Send Harsh a swipe-reply ask whose 'need' is the team's own work (record screen recordings, send the revised draft, publish the video).
Seen 1 time(s). Source: System check.
## A queued WhatsApp message is sent once
When: Asks and contract alerts queued while the chat was closed go out at the morning round-up or when the chat reopens
Do: Send each queued message once and mark it sent so no later run sends it again; before sending, check the same text has not already gone out since it was queued.
Never: Send the same ask or contract alert again on every heartbeat.
Seen 1 time(s). Source: System check.
## A file sent in the WhatsApp chat goes only to the brand named with it
When: Harsh or Pratham drops a contract or file into the WhatsApp chat, with or without a caption, and sometimes names the brand in the next message
Do: Match the file to a deal only from the brand named in the caption or the very next message, the file name, or the brand's name as whole words in the contract text. If the file name names a different company than the deal (Automate AI Consulting x Auremere is Lindsay's), or the brand is unclear, ask which brand and wait.
Never: Auto-send a signed contract to a deal matched by a few letters inside the contract text, or to a deal of a different creator than the one whose company is on the file.
Seen 1 time(s). Source: System check.
## One WhatsApp card per draft
When: A draft is shown to Harsh or Pratham on WhatsApp
Do: Send the draft card once; if the person writes again about the same draft, answer in text or act on it
Never: Send the same draft card twice in a row
Seen 1 time(s). Source: System check.
## "Add N videos" means new cards, not script notes
When: Harsh tells the PM on WhatsApp to add videos, cards or a multi-video campaign for a creator
Do: Create one card per video on that creator's board (with the brief link and date he gave) under the right deal, and ask once which deal it belongs to if unclear
Never: Never turn it into 'script feedback' for Rudraksh on an existing deal
Seen 1 time(s). Source: System check.
## A message about another creator or another brand never answers this question
When: Harsh writes on WhatsApp while a brand question for the same brand but a different creator is open (two ElevenLabs deals, one Duncan and one Chris).
Do: Match the answer on brand AND creator. If the message names another creator or carries a 'Creator X OtherBrand' label, treat it as news for that deal (or a new deal) and leave the open question waiting.
Never: Never write a reply from a message that names a different creator, and never state facts in a brand email ("we've checked, the post is live") that nobody gave you.
Seen 3 time(s). Source: System check.
## A file Harsh sends is never dropped
When: Harsh sends a file, code or link on WhatsApp while another draft for that brand is waiting
Do: Work out which brand and thread the file is for (ask once if unclear), then draft the email carrying that file word for word in that brand's thread, alongside any draft already waiting.
Never: Answer a file from Harsh with 'a reply for that thread is already waiting' and show the old draft instead.
Seen 1 time(s). Source: System check.
## Only use WhatsApp templates Meta has approved
When: The 24-hour WhatsApp window is closed and the PM needs to reach Harsh or Pratham
Do: Use a template name that exists and is approved in Meta; if a send fails with 'Template name does not exist', fall back to an approved template and raise it in #pm-alerts once.
Never: Ship a new template name in code before Meta approves it, or let failed pushes fail silently.
Seen 18 time(s). Source: System check.
## Brand requests at night are kept
When: A brand asks for something while WhatsApp is quiet or closed
Do: Queue the question and deliver it with the next message or the morning round-up.
Never: Drop it.
Seen 1 time(s). Source: Rulebook.
## 'Yes' confirms every proposed change
When: Harsh says yes to a list of changes on WhatsApp
Do: Apply all of them.
Never: Apply only the first one.
Seen 1 time(s). Source: Rulebook.
## Ask Harsh for things only we have
When: A brand asks for ad codes, a UID, an account email, a contract, files, alone or together with a script
Do: Ask Harsh on WhatsApp, then draft from his answer word for word.
Never: Draft a promise email instead.
Seen 8 time(s). Source: Rulebook.
## One WhatsApp message per thing
When: Alerting Harsh
Do: Send each thing once. Discord pm alerts are mirrored to WhatsApp, so never send both.
Never: Send near-duplicate messages or ask about team work (scripts, cuts, uploads).
Seen 4 time(s). Source: Rulebook.
## WhatsApp deals get WhatsApp alerts
When: A deal came in on WhatsApp
Do: Alert Harsh (script ready, posted).
Never: Email the brand. And never send a 'Script ready, send the brand on WhatsApp' PDF for a card of an EMAIL deal (cards (2), (3) of a deal are emailed with the deal's Script email).
Seen 2 time(s). Source: Rulebook.
